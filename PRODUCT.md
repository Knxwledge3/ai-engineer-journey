# Клиенты и продукт

Тема продукта пока не выбрана, и это нормально. Этот файл о том, как прийти к ней через реальные компании, а не через размышления.

## Логика на 10 недель

1. **Сначала чужая рутина, потом твоя идея.** Ты находишь компании, у которых люди каждый день делают руками одно и то же, и убираешь эту рутину.
2. **Сначала заказ, потом продукт.** Первый клиент платит за решение своей задачи. Если ту же задачу просит второй и третий, это уже продукт.
3. **Большая компания вырастает из повторения.** Не из одной гениальной идеи, а из задачи, которая встречается у многих и которую ты научился закрывать лучше других.

## Шаг 1 (неделя 1): список из 5 компаний

Для каждой компании, которой ты хочешь помочь, одна строка в `product/companies.md`:

| Компания или тип бизнеса | Кого я там знаю | Какая рутина, по-моему, съедает у них время | Откуда я это знаю |
|---|---|---|---|
| | | | |

Последний столбец важный: «видел сам» и «мне кажется» — разные вещи.

Как выбирать: малый и средний бизнес, где решение принимает один человек и ты можешь поговорить с ним на этой неделе. Крупные компании оставь на потом: там согласования идут месяцами.

## Шаг 2 (недели 2-3): 5 разговоров без продажи

Цель разговора — понять их день, а не рассказать про ИИ. 20 минут, пять вопросов:

1. Какую задачу ваши сотрудники делают каждый день и не любят?
2. Сколько человек и сколько часов в неделю на неё уходит?
3. Что происходит, когда её делают с ошибкой или с опозданием?
4. Как вы пробовали это решить? Что не сработало?
5. Если бы это исчезло завтра, что бы вы делали с освободившимся временем?

Правила:
- Спрашивай про прошлое и факты («когда это было в последний раз?»), а не про будущее («вы бы купили?»). На второй вопрос все из вежливости отвечают «да».
- Не показывай решение в первом разговоре. Бот из 11-го дня показывай во втором.
- Сразу после разговора пять строк в `product/interviews/`: что делают, сколько времени, во что обходится ошибка, цитата, твой вывод.

## Шаг 3 (недели 4-5): выбор одной задачи

Оцени каждую найденную задачу от 1 до 5:

| Вопрос | Задача 1 | Задача 2 | Задача 3 |
|---|---|---|---|
| Возникает каждую неделю или чаще? | | | |
| Человек назвал цену проблемы в часах или деньгах? | | | |
| Я могу сделать рабочую версию за 2 недели тем, что уже умею? | | | |
| Данные и доступы мне дадут? | | | |
| Та же задача есть ещё у двух компаний из списка? | | | |
| Мне интересно возиться с этим месяц? | | | |

Берёшь задачу с наибольшей суммой. Пятый вопрос — мостик от заказа к продукту.

## Шаг 4 (недели 6-8): пилот

Пилот — это маленький платный проект с ясной границей. Договорись письменно, хотя бы в мессенджере, о пяти вещах:

1. **Что именно делает решение** — одно предложение, без «и».
2. **Как поймём, что получилось** — число: «ответ клиенту уходит за 5 минут, а не за 2 часа», «из 20 заявок 18 разобраны верно».
3. **Срок** — две недели.
4. **Цена и порядок оплаты** — часть вперёд. Бесплатный пилот хуже платного: к бесплатному относятся несерьёзно и не дают данных.
5. **Что остаётся за рамками** — список того, чего ты не делаешь.

## Чужие данные

- Данные клиента не попадают в публичный репозиторий. Добавь `product/docs/` в `.gitignore` или заведи приватный репозиторий под клиента.
- До передачи данных в модель прочитай условия провайдера о хранении и использовании данных и скажи клиенту честно, куда уходят его документы.
- Персональные данные людей по возможности убирай до обработки.
- Для первого пилота бери процесс, где ошибка агента неприятна, но не катастрофична, и где человек проверяет результат перед отправкой.

## Правило узости

Сформулируй то, что делаешь, одной фразой:

> «Помогаю [кому именно] сделать [одно действие] по [одному типу документов или данных] за [время], а не за [сколько сейчас]».

Если во фразе есть «и», это слишком широко для первого пилота.

## Чего избегать

- **Платформа для всех.** «Универсальный ИИ-ассистент для бизнеса» не нужен никому конкретно.
- **Компания из агентов с первого дня.** Сначала один агент, который надёжно закрывает одну задачу. Надёжность — это проверки, ограничения и человек на опасных шагах, а не количество агентов.
- **Смена темы каждую неделю.** Новая идея идёт в `ideas.md` и ждёт воскресенья.

## Папка продукта

```
product/
  companies.md  список компаний
  interviews/   заметки с разговоров
  docs/         документы (чужие данные в git не кладём)
  evals/        cases.json и log.md с цифрами качества
  NOTES.md      решения и выводы
  ideas.md      парковка идей
  llm.py, api.py, bot.py, agent.py ...
```

До выбора темы (дни 1-9) в `product/docs/` положи любые 10-20 своих документов: инструкции, договоры, статьи. Для учёбы тема не важна, важны настоящие тексты.
