# AI Engineer Kit: курс с автопроверкой

Комплект для Ерса. 21 учебный день вместо 30, один сквозной продукт вместо разрозненных задач,
и проверка каждого шага тестами на твоём компьютере: без ИИ, без API-ключа, без интернета.

## Что внутри

| Файл или папка | Что это |
|---|---|
| `diagnostic/` | 8 задач на 45 минут. Определяет, с какого места и в каком темпе идти. |
| `days/d01 ... d21/` | На каждый день: README с заданием, заготовка кода, тесты. |
| `progress.py` | Таблица прогресса по всем дням одной командой. |
| `PLAN.md` | План v2: 21 день, правила перехода, недельный ритм. |
| `PRODUCT.md` | Как найти первого клиента и тему продукта. |
| `COURSES.md` | Какие курсы и разделы открывать под каждый день. |
| `RADAR.md` | Как держать обучение актуальным: еженедельный ритуал и готовый промпт. |
| `TUTOR.md` | Инструкция для любой ИИ-модели, чтобы она вела тебя как наставник. |
| `_solutions/` | Эталонные решения. Открывать только после своей сдачи (см. правило ниже). |
| `templates/tests.yml` | Готовый CI для GitHub (День 19). |

## Установка (Windows, один раз)

```
cd D:\123\ai-engineer-journey
```

Распакуй содержимое архива в корень репозитория, затем:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python progress.py
```

Должна появиться таблица, где у всех дней 0 сданных тестов. Это нормально: заготовки пустые.

## Первый шаг: диагностика

1. Поставь таймер на 45 минут. Без ИИ, без поиска готовых решений. Документацию Python читать можно.
2. Открой `diagnostic/diag.py` и реши, что успеешь.
3. `python progress.py diag` покажет результат и рекомендацию по темпу.
4. Пришли вывод наставнику: по нему корректируется план.

Диагностика измеряет не «умный ли ты», а сколько времени закладывать на Python. Ноль из восьми — нормальный результат для старта.

## Как проходит день

1. Прочитай `days/dNN/README.md`: зачем это нужно и что сделать.
2. Реши кату в `dNN.py`, пока `python -m pytest days/dNN -q` не станет зелёным.
3. Сделай «слой продукта»: примени сегодняшнее к своему продукту в папке `product/`.
4. Теорию смотри после первой попытки, а не до. Так она отвечает на твои вопросы.
5. Коммит. Потом ревью у наставника.

Застрял больше чем на 30 минут: попроси у наставника подсказку (не решение).

## Правило про `_solutions/`

Эталон нужен для сравнения после сдачи: твой код уже работает, и ты смотришь, как ту же задачу решил другой инженер. Если открыть его до сдачи, день не засчитывается: ты узнаешь чужой код, но не научишься писать свой.

## Почему тесты работают без модели

В каждой функции модель приходит параметром `llm`. В тестах это подставная функция, в продукте настоящая. Это не учебное упрощение, а рабочий приём: так пишут сервисы, которые можно тестировать и переводить с одного провайдера на другой за час. Поэтому курс не устареет, когда выйдут новые модели.
