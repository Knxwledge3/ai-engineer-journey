# Радар: как держать обучение актуальным

## Главная мысль

В ИИ быстро меняется верхний слой и почти не меняется нижний. План построен на нижнем.

| Не меняется годами (учим глубоко) | Меняется каждые месяцы (сверяем в день занятия) |
|---|---|
| Вызов модели через API, сообщения, роли | Имена и цены моделей |
| Промпт как код, evals, измерение качества | Конкретные фреймворки и SDK для агентов |
| Структурированный вывод и валидация | Параметры и названия функций в API |
| Поиск по смыслу, нарезка, RAG | Векторные базы, сервисы хостинга |
| Цикл агента: модель, инструменты, результат | Возможности «из коробки» (то, что вчера писали руками) |
| Ошибки, повторы, таймауты, трассировка | Инструменты автоматизации и их узлы |
| Безопасность: секреты, недоверие к чужому тексту | Конкретные приёмы атак и защит |
| Стоимость, бюджет, разговор с пользователем | Что модно в соцсетях на этой неделе |

Поэтому в катах нет ни одного имени модели и ни одного фреймворка. Имя модели живёт в `.env`, фреймворк выбирается на 14-й день.

## Ритуал: воскресенье, 30 минут

1. **15 минут: первичные источники.** Страницы обновлений (release notes, changelog) провайдеров, чьи модели ты используешь, плюс сайт протокола MCP. Не соцсети и не пересказы.
2. **10 минут: фильтр.** Для каждой новости три вопроса:
   - Это заменяет что-то, что стоит в моём плане на ближайшие 7 дней?
   - Это делает мой продукт заметно дешевле, быстрее или надёжнее уже сейчас?
   - Через месяц это будет важно, или это шум недели?
3. **5 минут: решение.** Ровно одно из трёх:
   - **Ничего не менять** (так должно быть в большинстве недель).
   - **Заменить ресурс**: тема дня та же, документация или инструмент другие.
   - **Заменить тему**: только если на первые два вопроса ответ «да».
4. Запиши одну строку в таблицу ниже.

Правило против распыления: новая вещь входит в план, только вытесняя старую. План не растёт.

## Промпт для радара

Вставь в любую модель с веб-поиском:

```
Ты помогаешь мне держать учебный план по AI-инженерии актуальным.
Мой план (темы по дням): [вставь таблицу из PLAN.md]
Я сейчас на дне: [N]. Мой продукт: [одна фраза].

Найди, что изменилось за последние 7 дней у крупных провайдеров моделей,
в протоколе MCP и в популярных агентных SDK. Используй только первичные
источники: официальные changelog, release notes, документацию. Дай ссылки.

Для каждого изменения ответь:
1. Заменяет ли оно что-то в моих ближайших 7 днях плана? Что именно?
2. Улучшает ли оно мой продукт уже сейчас? Как?
3. Это надолго или шум?

В конце дай ровно одно решение: «ничего не менять», «заменить ресурс
(какой на какой)» или «заменить тему (какую на какую)». Если сомневаешься,
выбирай «ничего не менять». Не предлагай добавлять темы без удаления других.
```

## Точки обязательной сверки в плане

| День | Что сверить с актуальной документацией |
|---|---|
| 2 | Имя модели и quickstart провайдера |
| 4 | Что API уже умеет в структурированном выводе само |
| 8-9 | Актуальные векторные базы; есть ли у провайдера встроенный поиск по файлам |
| 11 | Актуальная библиотека для Telegram |
| 15 | Текущая версия MCP и SDK |
| 16 | Какой агентный SDK сейчас основной у твоего провайдера |
| 19 | Цены и условия кэширования |

Раз в месяц сверяй и COURSES.md: курсы устаревают так же, как фреймворки.
